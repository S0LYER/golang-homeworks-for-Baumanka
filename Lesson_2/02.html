Язык

Не «как в Java»

Те же идеи — без иерархии классов. В Go ООП собирается из простых кирпичей.

Нет class

Данные — struct. Поведение — методы на типе. Наследования «extends» нет.

Композиция важнее

Собираем тип из частей, а не растим дерево предков. Меньше магии, больше явного кода.

Интерфейсы маленькие

Описываем, что тип умеет, а не кем он является. Реализация — неявная.

Три принципа

Как они выглядят в Go

Инкапсуляция

Пакет и регистр имени: Title видно снаружи, title — нет. Контракт вместо «всего наружу».

Наследование

Не иерархия классов, а композиция и embedding: встроили структуру — получили её поля и методы.

Полиморфизм

Интерфейс фиксирует поведение. Любой тип с нужными методами подходит — без implements.

Кирпич

Struct — данные типа

Структура собирает поля в одно значение. Это не класс: пока нет методов — это просто запись.

type Task struct {
    Title string
    Done  bool
}

t := Task{Title: "разобрать ООП"}  // Done == false — нулевое значение

Поведение

Методы: value и pointer

Value receiver

func (t Task) — копия. Читать удобно. Менять поля бессмысленно: оригинал не увидит.

Pointer receiver

func (t *Task) — работаем с тем же значением. Нужен, когда метод меняет состояние.

func (t Task) Label() string {  // копия: только читаем
    return t.Title
}

func (t *Task) Complete() {   // указатель: меняем Done
    t.Done = true
}

Инкапсуляция

Пакет решает, что видно

Видимость в Go — не private внутри типа, а граница пакета. Заглавная буква = экспорт.

Exported

Task, New, Title() — можно вызывать из другого пакета. Это публичный контракт.

Unexported

title, done, validate() — только внутри пакета. Прячем внутренности, оставляем методы.

Контракт

Поля прячем, методы оставляем

package task

type Task struct {
    title string  // снаружи не достучаться
    done  bool
}

func New(title string) (*Task, error) {
    if title == "" {
        return nil, errors.New("пустой заголовок")
    }
    return &Task{title: title}, nil
}

Наследование

Композиция вместо иерархии

Не «Task is-a Entity», а «Task has timestamps». Собираем поведение из частей.

Вложение поля

Явно: Meta Meta. Обращение через имя: t.Meta.CreatedAt. Всё видно.

Embedding

Безымянное поле: методы и поля «всплывают» на внешний тип. Это и есть go-шное «наследование».

Embedding

Встроили — получили методы

type Timestamps struct {
    CreatedAt time.Time
}

func (ts *Timestamps) TouchCreated() {
    ts.CreatedAt = time.Now()
}

type Task struct {
    Timestamps        // embedding: без имени поля
    title      string
}

t.TouchCreated()      // метод Timestamps доступен на Task
t.CreatedAt           // поле тоже «всплыло»

Полиморфизм

Интерфейс описывает умение

Не родословная типов, а набор методов. Реализация неявная: есть методы — тип подходит.

Маленький контракт

Один-два метода лучше «богатого» интерфейса. Проще подставить другой тип.

Нет implements

Не пишем «я реализую». Компилятор сам проверяет, совпадают ли сигнатуры.

Где уместно

Там, где поведение общее: «можно завершить», «можно сохранить». Не на каждый struct.

Поведение

Один интерфейс — разные типы

type Completer interface {
    Complete() error
}

func MarkDone(c Completer) error {
    return c.Complete()
}

// Task и любой другой тип с Complete() — подходят
var _ Completer = (*Task)(nil)  // проверка на этапе компиляции

Ошибки

error как значение и defer

Ошибка — не исключение

Метод возвращает error. Вызывающий решает: показать, обернуть, остановиться. nil — всё хорошо.

defer

Отложенный вызов: закроется файл, снимется блокировка — даже если вышли по ошибке. Пока без паники.

func (t *Task) Complete() error {
    if t.done {
        return errors.New("уже выполнена")
    }
    t.done = true
    return nil
}

Практика

Задачи в папках

Берём консольное приложение с первого занятия и дописываем домен: не пустые папки, а задачи внутри.

К концу занятия

Создание задачи в папке, список, смена статуса — через struct и методы, а не через набор строк в слайсе.

Что пишем

Расширяем приложение

  • Папки из домашки остаются: внутри больше не «задач пока нет».
  • Создать задачу в текущей папке, показать список, сменить статус.
  • Task — struct с методами, не свободные строки. Статус меняем методом с pointer receiver.
  • Ошибки: пустой заголовок, папки нет, задачу уже закрыли — error, не паника.
